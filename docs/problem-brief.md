# Problem Brief — 游木工坊

## Problem Statement

游木工坊目前是一個靜態一頁式展示網站，沒有後台管理與下單功能。店主無法透過後台更新商品與圖片，客戶也無法直接在網站下單，導致所有交易仍靠人工、社群媒體溝通，效率低落。

本專案目標：將現有靜態站點改造成前後端分離架構，讓店主可以管理商品與圖片、讓客戶可以在網站直接下單。

## 不解決（Non-goals）

- 線上付款 / 金流整合
- 庫存管理
- 多管理員帳號
- 通知系統（Email / LINE Notify）
- SEO / SSR 優化
- 行動 App

## 需求 → Phase 對應表

| 需求 | Phase |
|---|---|
| 全 Docker 開發環境（含測試） | P0 |
| DB schema 初始化 | P1 |
| 後台帳密登入（JWT） | P2 |
| 商品分類管理（後台自由新增） | P3 |
| 商品 CRUD | P3 |
| 商品圖片上傳（存 volume，DB 存路徑） | P4 |
| 訂單建立 API | P5 |
| 訂單狀態更新 API | P5 |
| 前台商品目錄（含分類篩選） | P6 |
| 前台購物車 | P6 |
| 前台下單表單 | P6 |
| 後台商品管理 UI + 圖片上傳 UI | P7 |
| 後台訂單列表 + 狀態管理 UI | P7 |

## 設計原則

1. FE 只呼叫 `/api/*`，不直接讀 DB 或 volume
2. 圖片路徑由 BE 維護（DB 存相對路徑），FE 收到的是完整 URL
3. 訂單寫入時快照 `unit_price`，商品改價不影響歷史訂單
4. 測試跑在 Docker 裡，host 環境不裝任何套件
